# 设施设备能源管理前端

作业标准维护检查要求；巡检／维保的周期计划绑定项目，复用巡更频次的星期、多时段、次数、最小间隔、指定日期及规则预览。巡检／维保内的“任务配置”选择项目、标准、周期计划、负责人和必填设备组；开始／结束时间放在任务配置中，在有效期内按引用规则生成工单。候选按项目过滤，切换项目清空引用；展示规则摘要及去重设备数。同一配置同一执行时隙生成整项任务，去重后的设备作为任务明细；项目所属组织的有效员工整项接单或被派单，逐设备填写检查结果并拍照，全部设备提交后由负责人审核；不再区分单、双工单或配置外协。编辑旧配置时须选择周期计划与设备组，不静默沿用旧间隔。

设备档案统一使用“启用巡检维保”开关；原任一开关开启视为启用，保存时同步两个历史字段。设备组成员候选只包含当前项目已启用巡检维保的设备，切换项目清空已选成员；保存与生成任务仍由服务端校验启用状态。

设备详情仅保留设施档案和操作历史；不在详情中加载能源映射、客户绑定或关联任务。设备档案分开展示 Cloud 名称和 Cloud 设备 ID；Cloud 名称随同步更新，下方可编辑的本地名称仅首次同步时初始化，后续同步不覆盖。

仪表配置的用途使用户用／公用选项，统计层级使用总表／分表／支路／其他；表格展示、编辑和搜索复用选项文案，保存与查询继续使用原始代码，旧自定义用途保留原文。

抄表与补录审核只查询累计读数和周期增量，服务端在计数、分页前与用户条件及资产范围取交集，其他遥测数据保留给监控。列表显示设备名称、项目和水／电／燃气仪表类型；设备名按当前页批量查询，设备筛选提交设备 ID，指标筛选提交指标类型，避免将属性代码当作状态翻译。来源显示 Cloud 采集／人工补录，人工补录保留原审核流程。

数据采集状态及抄表与补录审核的外层列表不显示空操作列。抄表页工具栏提供“人工补录”和“审核”。补录弹窗按项目搜索已配置的启用仪表，选择计量指标，填写原始读数、发生时间和原因，提交后进入待审核；原始读数以十进制字符串传递，由服务端换算。审核弹窗仅查询人工补录，默认待审核，支持已通过／已驳回／全部快捷筛选、条件搜索、详情和逐条通过／驳回；本人不能审核自己的补录。菜单按钮 `facility/Energy:manual-reading`、`facility/Energy:reading-review` 均沿用后端 `facility-mapping:save` 和设备资产写权限，需初始化菜单后授权使用。

“补录记录”弹窗只查询当前账号的人工补录，默认全部，支持待审核／已通过／已驳回／已重新提交及条件搜索。本人被驳回的记录可通过“重新编辑”修改原始读数、抄表时间和原因；项目、设备及指标锁定，编辑准确加载原设备映射，缺失或停用时明确阻止提交。重提成功后旧记录保持原读数并标记已重新提交，新申请重新待审；重复重提由后端版本校验拦截。按钮 `facility/Energy:reading-records` 使用查询权限，`facility/Energy:reading-resubmit` 使用保存权限，不依赖补录审核按钮。

PC 模块由 SaaS 运行端加载，模块名 `facility-energy-ui`。导航与当前报事报修一致：从 Cloud 项目应用卡片进入，`configuration.customDomain` 留空，沿用宿主一级侧栏及内容区下级导航，不要求 `navigationMode: tree`。设备、巡检、维保、故障、能源、预警、客户与报表访问 `/property/facility-energy/**`；组织、用户、空间、客户和字典页面统一复用 `property-base-ui`，访问共享 `/property/**`。

在运行端仓库根目录构建：

```sh
pnpm --filter facility-energy-ui build:with-base
```

类型检查使用 `pnpm exec vue-tsc --noEmit -p modules/facility-energy-ui/tsconfig.json`。模块保留宿主的 `@jetlinks-web-core/*`、`@/*` 和 `@theme-config` 路径别名；主题配置与 Vite 一致，优先使用运行端 `configs/theme/index.ts`，不存在时使用 Web Core 默认配置。共享宿主源码也会参与检查，需分别核对模块及宿主诊断。

`mobile-h5` 是设施员工独立移动入口，使用 Vant 4，按任务、故障及消息权限显示功能；不提供业主仪表入口。Node.js 要求 22.18 或更新版本。

移动端待接单详情使用任务信息、执行时间和设备清单等紧凑白色卡片，浅蓝灰背景及左右留白分隔；底部提供接单入口。不展示作业资料、未填写的结果、检查进度或空处理记录。移动端不提供关闭任务；转单仅限有分派权限的当前接单人，且任务处于已接单、执行中或整改状态，打开及提交时均检查资格。PC 管理端操作保持原有规则。

```sh
cd mobile-h5
npm ci
npm test
npm run build
```

部署时使用实际 `config.json` 指定 Cloud 项目编码、应用 ID、同源网关和物业电话。员工在线接单下载后可离线执行巡检／维保；缓存和附件按后端确认的账号／应用隔离，联网后使用版本及幂等键提交。维修和消息需要在线使用。

部署定义、角色说明和真实联调验收位于相邻 `property-management/deploy/facility-energy/README.md` 及 `ACCEPTANCE.md`。消息仅面向项目员工，不发送历史业主短信。构建结果不表示实际应用授权或 Cloud 设备联调已验收。

## 综合工作台

综合工作台采用运行状态与任务待办双栏布局，顶部仅保留项目下拉；保留宿主外层大面板，移除工作台灰色底板和额外内边距；任务待办、设备运行、能源用量用细边框与间距分区，不叠加背景或阴影。复用 `reports/overview` 和近24小时的 `reports/energy`。能源范围支持总表、分表、支路、其他，进入页面或切换项目时默认总表，不自动切换到其他层级，手动选择后保留当前范围，避免跨层级重复累计；层级切换只调用能源接口并在能源区域加载，待处理与设备数据保持显示。切换项目仍刷新整个工作台，旧能源请求不能覆盖新项目结果；能源错误支持局部重试，明细沿用同一范围。任务待办横排待接单、进行中、待审批、逾期四项；进行中含已接单、执行中和待整改，逾期与任务阶段可以重叠，不可相加。点击待接单、进行中、逾期可选择巡检／维保并携带项目与状态下钻；待审批按当前负责人统计，且需对应审批按钮权限，直接打开现有审批弹窗并默认当前项目。下方保留今日作业，预警与通知失败收为轻量异常提醒入口。水、电、燃气分别汇总，单位不兼容明确标注，接口失败时不显示虚假零值。

实现入口：`views/facility/Overview/index.vue`、`hooks/useOverview.ts`、`shared/overview.ts`、`components/overview/OverviewEnergy.vue`；页面只负责呈现，hook 负责项目联动及菜单跳转，共享函数负责单位汇总与快捷条件。复用菜单权限、条件筛选和表格。验证：37项相关回归及模块构建通过，模块类型诊断为0（宿主与第三方已有类型错误仍阻断完整类型检查）；浏览器核对5G园区10台在线设备、5项逾期、今日2项巡检，与数据库一致；验证项目切换与携带条件跳转、采集页签定位、明细弹窗、断网重试以及900／1280／1440宽度布局。当前无总表映射，默认总表显示空态；手选分表可查看6个表计，其他层级可查看另4个表计，明细与所选范围一致。900宽度无横向溢出；浏览器限速验证层级切换仅新增1次能源请求，只有能源区域出现加载，上方设备总数保持10。工作台与用能明细不展示数据不完整提示，读数及汇总校验逻辑保持不变。

## 公共基础前端

宿主同时检出并加载 `modules/property-base-ui`（`2.20`）。本模块不再提供组织、用户、空间、客户、字典的菜单、页面、接口封装或语言副本。公共菜单由公共模块唯一提供给宿主初始化，各应用按职责引用并授权公共 `charging/*` 菜单；不在业务 `baseMenu.json` 中复制公共定义。后端仍由独立基础服务维护统一数据。

在宿主执行 `pnpm --filter facility-energy-ui dev` 联合调试公共和认证模块；`build` 仅构建设施独立模块，`build:with-base` 包含设施、公共基础页面及认证模块，输出宿主 `dist/`，避免菜单存在但组件缺失。部署至独立静态目录时，通过宿主构建所选模式的 `.env.<mode>` 配置 `VITE_PUBLIC_PATH`，并验证生成入口中的资源前缀。正式 SaaS 集成构建还须包含运行端、认证与实际使用的其他模块；宿主 `pnpm build:property-apps` 覆盖报修、品质、设施与公共模块。

菜单初始化与项目授权树中，设施业务统一位于一级“设施设备”下，保留原页面、按钮编码和隐藏的移动端授权节点；“物业基础管理”由公共模块并列提供。进入独立应用时，通过宿主菜单过滤扩展仅展开已授权的“设施设备”分组，沿用原业务导航，不补充未授权菜单或按钮，也不展开公共基础分组。更新已有环境时需重新初始化菜单，并同步应用模板和角色菜单，源码改动不会直接修改已保存的菜单。

已有环境的旧菜单不会因源码删除自动消失，按后端 `deploy/property-base/README.md` 增量迁移模板、套餐、订阅与角色，保留原资产范围，验收后停用旧基础副本。不重置业务菜单，也不全量初始化其他系统。

设备同步状态、应用操作日志为设施业务功能，保留原菜单 ID、URL、权限与组件，归入“设施设备”；设备、员工、业主资格继续通过设施后端的业务接口校验。

作业标准随巡检／维保入口固定作业类型，必填且不可编辑；不再录入作业指导书和附件，已有指导书数据保持兼容。检查项采用紧凑表格编辑，填写方式、必填及拍照要求对齐展示；数值项配置正常范围，新增检查项默认单选并要求拍照，单选项固定为“符合／不符合”，不再提供“是否”类型或自定义选项，保存前提示具体检查项的问题。

巡检／维保管理各有五个真实子菜单，顺序为任务、作业标准、周期计划、任务配置、设备组；各自独立路由、查询和按钮授权，不再使用业务页签。作业类型由菜单入口固定，候选限定同项目同类型；设备组数据按项目共享，不增加作业类型筛选。保存启用后按周期自动生成；单次任务在周期计划高级配置中指定日期和时段，不提供手动生成或临时任务入口。新增／编辑、删除、启停、执行、分派、审核及二维码权限归属相应子菜单，父分组不捆绑子菜单写权限。

任务页“审批”打开当前负责人的审批弹窗，使用 JetLinks 表格和条件搜索，支持待审批、已通过、已驳回、全部切换；待审批可逐条或批量通过／驳回，失败任务单独反馈。驳回后由原接单人整改并重新提交。任务操作列支持派单、转单和关闭，详情不提供撤回；关闭后保留历史。关闭使用独立 `close` 按钮权限，派单和转单共用 `dispatch`，审批使用 `review`。启停操作使用普通链接色，删除使用危险色。

初始化授权需覆盖独立使用场景：设备资产内的设备组使用该菜单自己的新增编辑、删除和二维码按钮；巡检／维保入口继续各自取权。员工移动端独立配置执行、派单转单、审批和关闭按钮。任务查询包含照片读取，执行和设备档案维护包含必要的文件上传权限，不要求额外授权其他业务菜单。通过菜单初始化筛选及独立菜单授权回归核对权限，数据范围和操作资格仍由服务端校验。

周期计划的预警时间由用户填写，按每次任务开始后经过的时间提醒，至少为单次执行时长的一半且早于结束时间。H5 消息入口支持任务、故障、预警和审批分类、未读筛选、逐条已读和全部已读；消息按账号、应用、项目及业务资产权限隔离。任务执行仍须扫描匹配的设备或设备组二维码。

## 故障、预警与员工消息

故障按登记、派单、接单、开始维修、提交验收、验收通过或驳回流转；关闭与维修完成分开统计。维修人和验收负责人必须是项目所属组织中具有相应权限的有效员工，维修人不能自验；负责人失效后由具有派单权限的管理员更换并说明原因。操作携带版本，记录过程和现场／维修照片。H5 仅展示当前员工可执行的接单、开始、提交或验收动作，管理端负责派单、转单、更换负责人及关闭。

预警扫描与消息提醒独立于历史遥测回补执行，慢回补不会阻塞预警；预警规则按项目、设备组或设备范围配置离线、上报中断、指标异常等条件；系统异常／恢复状态与人工处理状态独立。持续异常合并，恢复后再触发保留新一轮事件；转故障保留关联，不能把人工处理视为设备自动恢复。消息通知页展示员工业务消息及项目通知开关，历史业主渠道已停发。菜单初始化后需授予 `facility-message` 的查询／配置权限，以及 `facility-fault` 的派单／验收／关闭权限；已有数据库角色不会随源码自动扩权。

统计报表提供作业、故障与预警、能源分析，按项目及期间筛选，图表支持明细与原记录跳转、当前结果导出。作业按父任务计数，设备子任务不重复累加；按时率只计算已到期的有效任务。能源按所选层级与单位汇总，不跨总表／分表相加；缺有效读数或无可比历史时不展示虚假零值及增长率。

计费出账台账与审核弹窗提供全部费用、水费、电费、燃气费快捷筛选及费用类型标签（水费青色、电费紫色、燃气费橙色）；分类与组件搜索、审核状态共同过滤，分页和总数由服务端按完整条件计算。已出账分类读取落账快照，不随当前设备归属或收费标准变化。审核全部成功时仅短暂提示，部分失败时保留处理数量和失败原因供核对。

离线模式启用前预载作业路由，并在生产构建中等待 Service Worker 激活、核对静态资源完整性；准备失败不标记为已启用。Worker 只缓存构建白名单静态资源，不缓存 API 或账号令牌响应。断网下读取当前账号离线快照，提交保存在本地，恢复网络后由员工手动同步；关闭前确认清空缓存，不自动丢弃未同步数据。

任务配置的 nextRunTime 为服务端计算的只读排程字段，保存时忽略客户端回传值；周期结束后的配置仍可正常编辑及启停。
